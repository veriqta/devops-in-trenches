# Errata

This section records confirmed errors in released DevOps in the Trenches material.

## Check Existing Corrections

Review [corrections.md](corrections.md) before reporting an issue. A correction may already exist for the edition or repository version you are reading.

## Report a Possible Error

Use the technical-correction issue template and provide:

1. The edition, release tag, or commit identifier.
2. The file, chapter, heading, page, or paragraph.
3. The current wording or behavior.
4. A concise explanation of the problem.
5. The proposed correction, if known.
6. An authoritative source for technical claims.

Quote only the minimum text required to locate the issue.

## What Belongs in Errata

Errata includes confirmed:

- Technical inaccuracies.
- Incorrect commands or configurations.
- Definitions that change the meaning of guidance.
- Broken or incorrect references.
- Contradictions between released files.
- Material spelling, formatting, or numbering errors.

Differences of architectural preference are not automatically errors. A report should explain the relevant constraints and distinguish factual inaccuracy from context-dependent judgment.

## Sensitive Information

Do not include credentials, private keys, customer information, confidential incidents, restricted architecture, unpublished vulnerabilities, or proprietary evidence in a public report.

## Correction Process

Confirmed corrections are added to [corrections.md](corrections.md) with the affected version, original text or issue, corrected guidance, date confirmed, and status. Material repository changes are also recorded in the root [CHANGELOG](../CHANGELOG.md).
